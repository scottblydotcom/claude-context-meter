**Goal:** Reposition the app for Claude Code CLI users in a world where the Claude Desktop app now natively shows context, 5-hour, and weekly meters — by fixing the now-wrong 1M context denominator for Opus 4.7, retiring metrics that depend on the (now-removed) peak-pricing model, and rewriting the README to make the menu-bar niche explicit.

**Architecture:** Three small, independent changes against the existing Swift/SwiftUI menu-bar app. (1) Extend `ModelLimits` to detect Opus 4.7 1M sessions and return a 1M context limit. (2) Remove cost-weighted and peak-adjusted weekly metrics from `WeeklyUsageMetrics`, `WeeklyUsageCalculator`, and `WeeklyUsageSection` — peak pricing was removed by Anthropic on 2026-05-06, so peak-adjusted is meaningless and cost-weighted's only purpose (proxying server-side weighting) is now obsolete. (3) Rewrite README to lead with the CLI-user menu-bar niche, link to Anthropic's native meter, and document the limits the app cannot reproduce.

## Task 1: Detect Opus 4.7 1M sessions and persist the 1M limit across autocompaction

**Design:** Both Opus 4.7 variants use the model string `claude-opus-4-7`. Detection is reactive — once a session's `totalTokens` exceeds 200,000, we know it must be a 1M session and store that fact in `UserDefaults` keyed by `sessionId`. On every subsequent read (including after autocompaction resets the token count), the stored value wins. Keys older than 30 days are pruned on each call to prevent unbounded accumulation.

- [ ] **Step 3: Replace `ModelLimits.swift` with the session-persisted detection logic**

```swift
import Foundation

enum ModelLimits {
    static let defaultContextWindow: Int64 = 200_000
    static let extendedContextWindow: Int64 = 1_000_000

    /// Only the Opus 4.7 model can use the extended 1M context window.
    private static let extendedContextModel = "claude-opus-4-7"

    /// Returns the context window limit for a session.
    ///
    /// Both Opus 4.7 variants (200k and 1M) report the same model string in JSONL.
    /// Detection is reactive: once `observedTokens` exceeds 200k for a given session,
    /// the 1M limit is persisted in UserDefaults so it survives autocompaction.
    /// Keys older than 30 days are pruned on each call.
    static func contextWindow(for model: String, sessionId: String, observedTokens: Int64) -> Int64 {
        guard model == extendedContextModel else { return defaultContextWindow }

        let limitKey = "sessionLimit_\(sessionId)"
        let dateKey  = "sessionLimitDate_\(sessionId)"
        let defaults = UserDefaults.standard

        pruneStaleEntries(defaults: defaults)

        // Already confirmed as 1M in a prior call — honour across compaction
        if defaults.bool(forKey: limitKey) {
            return extendedContextWindow
        }

        // First time we observe tokens exceeding the 200k boundary
        if observedTokens > defaultContextWindow {
            defaults.set(true, forKey: limitKey)
            defaults.set(Date(), forKey: dateKey)
            return extendedContextWindow
        }

        return defaultContextWindow
    }

    // MARK: - Private

    private static func pruneStaleEntries(defaults: UserDefaults) {
        let cutoff = Date().addingTimeInterval(-30 * 24 * 60 * 60)
        for key in defaults.dictionaryRepresentation().keys where key.hasPrefix("sessionLimitDate_") {
            if let date = defaults.object(forKey: key) as? Date, date < cutoff {
                let sessionSuffix = key.dropFirst("sessionLimitDate_".count)
                defaults.removeObject(forKey: "sessionLimit_\(sessionSuffix)")
                defaults.removeObject(forKey: key)
            }
        }
    }
}
```

```markdown
# Claude Context Meter

A macOS menu bar app that shows Claude Code usage at a glance — without opening the Claude Desktop app.

**Built for Claude Code CLI users.** Anthropic's Claude Desktop app (as of 2026) now natively shows context window, 5-hour, and weekly usage in Settings → Usage. If you live in the Desktop app, you don't need this. This app exists for people who work primarily in the Claude Code CLI or in IDE extensions and want the same numbers in the macOS menu bar without context-switching.

## What it shows

- **Context window** — current session's token usage vs the model's limit. Detects Opus 4.7 1M sessions automatically (1M limit); all other models use 200k.
- **5-hour billing window** — output tokens used since the start of the current 5-hour window, with a configurable cap. ±1h accuracy due to no server-side window data.
- **Weekly usage** — three local counts: all tokens, excluding cache reads, and input+output only. Useful as a relative trend indicator; not a 1:1 match for Anthropic's server-side weekly %.

## What it cannot show

These are exposed by Anthropic's Desktop app and would require a server-side API the app does not have:

- Exact weekly % matching Anthropic's "Plan usage"
- Per-bucket weekly breakdown (All models / Sonnet only / per-app)
- Context category breakdown (Messages / System tools / Skills / MCP / Memory / Autocompact buffer)

For these, open Claude Desktop → Settings → Usage.
```
